# Authoring a module

How one module of the course is built. Module 07 is the worked example: read its files next to this guide.

## Files of a module

| File | Purpose |
|---|---|
| `lectures/NN-slug/index.html` | the lecture |
| `lectures/NN-slug/widgets.js` | its interactive widgets, if any |
| `labs/NN-slug/NN-slug.lab.py` | the lab, jupytext percent format, with solution blocks |
| `labs/NN-slug/README.md` | task table, prerequisites, where to get help |
| `src/freshcast/...` | reference code with solution blocks |
| `src/coursekit/checks/mNN.py` | one check per task |
| `tutor/notes/NN.md` | tutor notes |
| `docs/glossary.md`, `docs/standard.md` | new terms and rules the module introduces |
| `lectures/index.html` | turn the module's card from `div.module.soon` into a link |

`labs/NN-slug/NN-slug.solution.ipynb` is generated by the release tool. Commit it, do not edit it.

## Order of work

1. Reference code in `src/freshcast/`, without markers, until it works on the real data.
2. Checks, passing on the reference.
3. Solution markers, then `tools/verify.py`.
4. The lab notebook around the working code.
5. The lecture, last: it teaches exactly what the lab needs, in the lab's vocabulary.
6. Tutor notes, from the mistakes you made or almost made in steps 1-4.

- The block becomes `raise NotImplementedError("Zadanie 07.5")` in the learner view.
- For notebook cells give a friendlier stub:

  ```python
  # >>> SOLUTION 07.5
  corr_lag = float(panel[TARGET].corr(panel["sale_amount_lag_7"]))
  # --- STUB
  #| corr_lag = ...
  # <<< SOLUTION
  ```

- The task id is `NN.k`. The module number drives `course catchup`, so a block belongs to the module in which the learner writes it.
- Everything outside the blocks is given to the learner: signatures, docstrings, imports used by signatures. Imports used only inside blocks are removed from the learner view automatically.
- A docstring states behaviour completely enough to implement from: arguments, result, errors, edge cases. It does not describe the implementation.

## Checks

```python
@task("07.5", "add_lag, add_rolling_mean, dow_profile: obliczenia wewnątrz serii")
def check_panel_ops(_target: object) -> None:
    from freshcast.data import panel  # import inside: stubs must not break collection

    ...
    expect(condition, "Polish message: what is wrong, with the values seen")
```

- One check per task id. Inside, go from basic requirements to subtle ones, so the first failing message is the most useful one.
- Inputs: tiny hand-made frames for logic, `fixtures/frn_sample.parquet` for realistic data. Expected values are constants you measured, never a second implementation.
- Test the input is not mutated, the error cases named in the docstring, and the trap the module teaches (for 07.5: cross-series leak, window including today).
- A check for notebook-only modules (01-03) receives the learner's object: `check("01.3", my_function)`.
- Environment checks that have no reference solution are registered with `graded=False`.

## Lab notebook

- Opens with what gets built, the time, how to work, and a task table.
- Per task: why it matters (two or three sentences), a given demo of the trap where there is one, the task statement with the target file, three hints in `<details>` (direction, approach, near-code), the `check("NN.k")` cell, then use of the learner's function on the real data with one or two small exploration questions.
- Exploration answers are written by the learner into variables that the notebook then prints or asserts. Keep assertions profile-independent.
- The notebook must run top to bottom, solved, on the `standard` and `small` profiles, in under two minutes.
- Charts use `coursekit.plotting.use_course_style()`, one y-axis per chart, a title that says what is plotted.
- Planned traps: let the learner fall in, show the symptom, then ask for the cause.

## Lecture

One HTML page, 45-60 minutes of reading and interaction. Copy the head, top bar, page grid and footer from `lectures/07-pandas-panel/index.html`.

Components (all in `lectures/assets/course.css` and `course.js`):

| Component | Markup |
|---|---|
| Section | `<section id="slug"><h2>...</h2>` feeds the table of contents |
| Quiz, one answer | `<div class="quiz" id="q1" data-type="single">` with `.quiz-q` and `ul.quiz-options > li[data-correct]`; each `li` ends with `<span class="why">` |
| Quiz, several answers | same with `data-type="multi"` |
| Predict, then run (modules 01-05) | `<div class="predict" id="p1" data-type="single">` with `pre > code.language-python` and options; runs in Pyodide |
| Editable exercise | `<div class="pyrun" id="e1">` with `script[type="text/x-python"][data-role="starter"]` and `[data-role="test"]` |
| Callout | `<div class="callout rule|trap|story">` with `<span class="label">` |
| Widget | `<figure class="widget" id="...">`, logic in the module's `widgets.js`, helpers from `window.Course` |
| Steps with ticks | `ol.steps > li.step#id` with `label.tick > input[type=checkbox]` |

Rules:

- Every quiz option carries a `why`. A wrong option's `why` names the misconception behind it.
- Ids are unique per page; progress is stored under them.
- Open with a concrete failure the module prevents, then the list of what the learner will be able to do.
- A rule that enters `docs/standard.md` appears as `callout rule`, in the same words.
- Widgets compute in the browser on tiny tables, or show measured numbers from the real data. State which.
- Charts follow the palette and mark rules already in `course.css` (`--series-1..4`, thin bars, labels in ink not in series colour, a legend for two or more series, a hover tooltip, a table view).
- In code blocks escape `<` and `&`. Use `language-python`, `language-bash`, `language-ini`, `language-text`.

## Tutor notes

`tutor/notes/NN.md`, in English: what the learner should own afterwards, facts about the data worth having at hand, per task the common mistakes with a leading question for each, what good answers to the written questions contain, a quiz bank. No solution code.

## Writing

- Polish, second person singular, plain words, short sentences. No em dashes. Sentence-case headings.
- A sentence that could appear unchanged in another course says nothing about this one: replace it with the fact, the number or the instruction.
- English technical terms, Polish meaning once at first use and in the glossary.
