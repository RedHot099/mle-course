    Setup

    Przygotujesz komputer do pracy z kursem: zainstalujesz potrzebne narzędzia, pobierzesz projekt i uruchomisz pierwsze sprawdzenia. Wykonuj kroki po kolei. Dalszą konfigurację możesz przejść samodzielnie albo z pomocą tutora.

    • Czas: 2-4 godziny, zależnie od łącza i szczęścia
    • Wynik: działające środowisko, pobrane dane, pierwszy pull request

    Na początku nie musisz znać wszystkich opcji poleceń. Przy każdym kroku sprawdź za to, czy otrzymujesz opisany wynik. Wyjaśnienia narzędzi poznasz w kolejnych modułach.

    Po wykonaniu kroku zaznacz pole „Zrobione”. Strona zapamięta zaznaczenia w tej przeglądarce.

    Linux

    Jeśli korzystasz z Linuksa, pomiń instalację WSL2 i zacznij od kroku 4. Poniższe polecenia przygotowano dla Ubuntu 24.04. Na innej dystrybucji użyj jej menedżera pakietów zamiast apt. Sterownik NVIDIA zainstaluj według instrukcji swojej dystrybucji.

    Windows: WSL2 i Ubuntu

    Potrzebujesz Windows 11 albo Windows 10 w wersji 2004 lub nowszej.

    1. Zainstaluj WSL2 z Ubuntu 24.04

      W menu Start wyszukaj PowerShell. Kliknij go prawym przyciskiem myszy i wybierz Uruchom jako administrator. W otwartym oknie wpisz:

      wsl --update
wsl --install -d Ubuntu-24.04

      Uruchom komputer ponownie. Po restarcie Ubuntu poprosi o utworzenie nazwy użytkownika i hasła. Będzie to osobne konto linuksowe, niezależne od konta Windows. Podczas wpisywania hasła nie zobaczysz znaków na ekranie. To prawidłowe zachowanie.

      Jeśli instalacja stoi na 0%, przerwij ją i użyj wsl --install --web-download -d Ubuntu-24.04.

      Sprawdzenie, w PowerShell:

      wsl -l -v

      W kolumnie VERSION przy Ubuntu-24.04 ma być 2.

    2. Sprawdź, ile pamięci dostaje Linux

      Przy domyślnym ustawieniu WSL Linux otrzymuje połowę pamięci komputera, czyli 8 GB na laptopie z 16 GB RAM. Kurs dobierze do dostępnej pamięci odpowiedni profil danych. Jeśli chcesz zwiększyć limit WSL, utwórz w Windows plik %UserProfile%\.wslconfig:

      [wsl2]
memory=12GB

      Po zmianie wykonaj w PowerShell wsl --shutdown i otwórz Ubuntu ponownie.

      Sprawdzenie, w Ubuntu:

      free -h

      Kolumna total w wierszu Mem pokazuje pamięć widoczną dla Linuksa.

    3. Sterownik karty NVIDIA

      Zainstaluj aktualny sterownik NVIDIA w Windows, korzystając ze strony producenta. Może to być sterownik Game Ready albo RTX.

      W Ubuntu uruchomionym przez WSL nie instaluj osobnego sterownika NVIDIA. Dostęp do karty zapewnia sterownik Windows; dodatkowy sterownik linuksowy może zakłócić jego działanie.

      Karta przyda się dopiero w module 18, ale problemy ze sterownikiem lepiej znaleźć teraz. Biblioteki z tego modułu wymagają sterownika w wersji 580 lub nowszej.

      Sprawdzenie, w Ubuntu:

      nvidia-smi

      Ma się pojawić tabela z nazwą Twojej karty i wersją sterownika.

    Ubuntu: podstawowe narzędzia

    Od tego miejsca wszystko wpisujesz w terminalu Ubuntu.

    1. Zainstaluj git, curl i libgomp

      sudo apt update
sudo apt install -y git curl libgomp1

      sudo poprosi o hasło konta linuksowego. libgomp1 to biblioteka systemowa, bez której nie uruchomi się LightGBM z modułu 10.

      Sprawdzenie:

      git --version

    2. Załóż konto GitHub i zrób fork kursu

      Fork to Twoja kopia repozytorium kursu na GitHubie. Będziesz w niej zapisywać własną pracę i wysyłać zmiany. Utwórz ją według poniższych kroków.

      1. Załóż konto na github.com, jeśli go nie masz.
      2. Otwórz repozytorium kursu i kliknij Fork.
      3. Zostaw zaznaczoną opcję kopiowania tylko gałęzi domyślnej. Gałąź z rozwiązaniami pobierzesz osobno, gdy będzie potrzebna.

      Sprawdzenie: w przeglądarce widzisz repozytorium TWOJ-LOGIN/mle-course.

    3. Sklonuj fork do katalogu domowego Linuksa

      Wstaw swój login w miejsce TWOJ-LOGIN.

      cd ~
git clone https://github.com/TWOJ-LOGIN/mle-course.git
cd mle-course
      Pułapka

      Sklonuj projekt do systemu plików Linuksa, pod ścieżką zaczynającą się od /home/. W WSL unikaj folderu na dysku Windows, na przykład /mnt/c/: praca z plikami projektu może być tam znacznie wolniejsza.

      Sprawdzenie:

      pwd

      Ścieżka zaczyna się od /home/.

    4. Zainstaluj uv i środowisko kursu

      curl -LsSf https://astral.sh/uv/install.sh | sh

      Zamknij terminal i otwórz go ponownie, żeby polecenie uv było widoczne. Potem, w katalogu kursu:

      cd ~/mle-course
uv sync

      uv sync pobiera Pythona 3.12 i wszystkie biblioteki w wersjach zapisanych w pliku uv.lock. Pierwszy raz trwa kilka minut.

      Sprawdzenie:

      uv run course doctor

      Polecenie wyświetli listę sprawdzeń. Niektóre wyniki na tym etapie mogą być czerwone, ponieważ nie zakończyliśmy jeszcze konfiguracji. W następnej części zajmiesz się nimi po kolei.

    Dalej z tutorem

    Pozostały konfiguracja gita, logowanie do GitHuba z terminala, ustawienie edytora, pobranie danych i pierwszy pull request. Wybierz poniżej pracę z tutorem albo instrukcję do samodzielnego wykonania.

    Ścieżka z tutorem (zalecana)

    Tutor to agent AI uruchamiany w katalogu kursu. Ten kurs opisuje pracę z Claude Code, które wymaga płatnego planu (Pro wystarcza). Instrukcje tutora są w pliku AGENTS.md, więc zadziałają też w innych narzędziach, które ten plik czytają.

    1. Zainstaluj Claude Code i uruchom /setup

      curl -fsSL https://claude.ai/install.sh | bash

      Otwórz nowy terminal, wejdź do katalogu kursu i uruchom:

      cd ~/mle-course
claude

      Przy pierwszym uruchomieniu zalogujesz się przez przeglądarkę. W WSL może pojawić się kod do wklejenia. Potem wpisz:

      /setup

      Tutor uruchomi course doctor i pomoże Ci przejść przez niezaliczone sprawdzenia. Przy każdym poleceniu wyjaśni jego działanie i oczekiwany wynik. Na koniec wspólnie przygotujecie pierwszy pull request.

      Sprawdzenie:

      uv run course check 00

    Ścieżka bez tutora

    Poniżej znajdziesz te same kroki do samodzielnego wykonania. Po każdym z nich uruchom uv run course doctor i sprawdź, które elementy konfiguracji są już gotowe.

    1. Przedstaw się gitowi

      git config --global user.name "Imię Nazwisko"
git config --global user.email "ty@example.com"

      Git zapisze tę nazwę i adres e-mail przy każdym Twoim commicie. Podaj adres powiązany z kontem GitHub.

    2. Zaloguj się do GitHuba z terminala

      Zainstaluj gh według oficjalnej instrukcji dla Debiana i Ubuntu. Wersja z domyślnego repozytorium Ubuntu jest przestarzała. Potem:

      gh auth login

      Wybierz GitHub.com, HTTPS, zgodę na uwierzytelnianie gita i logowanie przez przeglądarkę.

      Sprawdzenie:

      gh auth status

    3. Dodaj repozytorium kursu jako upstream

      origin to Twój fork. upstream to oryginał, z którego pobierasz aktualizacje kursu i gałąź z rozwiązaniami.

      git remote add upstream https://github.com/RedHot099/mle-course.git
gh repo set-default TWOJ-LOGIN/mle-course

      Drugie polecenie sprawia, że pull requesty domyślnie trafiają do Twojego forka, a nie do repozytorium kursu.

      Sprawdzenie:

      git remote -v

    4. VS Code

      Zainstaluj VS Code w Windows, nie w Ubuntu. Dodaj rozszerzenie WSL (ms-vscode-remote.remote-wsl). Potem w terminalu Ubuntu:

      cd ~/mle-course
code .

      Otworzy się okno VS Code połączone z Linuksem. W tym oknie zainstaluj rozszerzenia Python i Jupyter. Muszą być zainstalowane "w WSL", VS Code zaproponuje to sam.

      Sprawdzenie: w lewym dolnym rogu okna jest napis WSL: Ubuntu-24.04.

    5. Pobierz dane

      uv run course data
uv run course doctor

      Pierwsze polecenie pobierze około 110 MB danych i sprawdzi, czy pliki są zgodne z oczekiwanymi sumami kontrolnymi. Drugie ponownie oceni środowisko. Po zakończeniu konfiguracji wszystkie sprawdzenia powinny być zaliczone.

      Na końcu zobaczysz profil danych dobrany do pamięci komputera. Określa on wielkość zbioru używanego w ćwiczeniach.

    6. Pierwszy pull request

      Utwórz dziennik nauki. Zapisuj w nim ukończone zadania, napotkane trudności i pytania, do których chcesz wrócić.

      git switch -c setup/journal
mkdir -p notes
code notes/journal.md

      Napisz kilka zdań: po co robisz ten kurs i co chcesz umieć za trzy miesiące. Zapisz plik. Potem:

      git add notes/journal.md
git commit -m "Add learning journal"
git push -u origin setup/journal
gh pr create --fill

      Otwórz link, który wypisze ostatnie polecenie. Obejrzyj zakładkę "Files changed", a potem kliknij Merge pull request. Wróć na gałąź główną:

      git switch main
git pull

      Sprawdzenie:

      uv run course check 00

    Polecenia, których będziesz używać codziennie

    PolecenieCo robi
    uv run course doctorSprawdza środowisko

    uv run course profile smallZmienia profil danych
