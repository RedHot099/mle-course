    Struktury danych i przepływ

    Co się stanie, gdy przypiszesz listę do drugiej zmiennej, a potem zmienisz jeden z jej elementów? W tym wykładzie prześledzisz takie sytuacje. Nauczysz się też wybierać kolekcje, odczytywać pliki i rozpoznawać błędne dane.

    • Czas: około 60 minut
    • Wymagane: zmienne, pętle, funkcje, listy i słowniki
    • Potem: lab 01, około 6 godzin

    Po tym wykładzie będziesz umiał:

    • przewidzieć, kiedy zmiana jednej zmiennej zmienia też inną,
    • dobrać listę, krotkę, słownik albo zbiór do zadania,
    • pisać comprehensions i generatory zamiast pętli budujących listy,
    • czytać plik linia po linii i zamykać go zawsze, także przy błędzie,
    • zgłaszać i łapać wyjątki tak, żeby komunikat mówił, co jest nie tak.

    Przy każdym przykładzie najpierw spróbuj przewidzieć wynik. Dopiero potem uruchom kod i porównaj odpowiedź z wyjaśnieniem. Pierwsze uruchomienie wymaga internetu i chwili oczekiwania na pobranie Pythona do przeglądarki.

    Nazwy i obiekty

    W Pythonie kilka zmiennych może wskazywać ten sam obiekt. Przypisanie b = a nadaje obiektowi drugą nazwę, ale go nie kopiuje. Jeśli tym obiektem jest lista, zmiana wykonana przez b będzie widoczna także przez a.

    prices = [10, 12, 15]
promo = prices
promo[0] = 8
print(prices)
    • [10, 12, 15]Tak by było, gdyby promo = prices robiło kopię. Nie robi.
    • [8, 12, 15]Tak. prices i promo to dwie nazwy jednej listy. Zmiana przez jedną jest widoczna przez drugą.
    • Błąd: nie można zmieniać promoListę można zmieniać przez każdą nazwę, która na nią wskazuje.

    Stąd biorą się dwa różne pytania o równość:

    • a == b pyta, czy obiekty mają taką samą wartość.
    • a is b pyta, czy to ten sam obiekt.
    a = [1, 2]
b = [1, 2]
c = a
print(a == b, a is b, a is c)
    • True True Truea i b powstały z dwóch osobnych literałów, więc to dwie różne listy o tej samej zawartości.
    • True False TrueTak. Ta sama wartość, dwa obiekty. c to druga nazwa listy a.
    • False False True== porównuje zawartość, a ta jest identyczna.
    Reguła

    is używaj tylko do porównań z None: if value is None. Wszędzie indziej chodzi Ci o wartość, czyli o ==.

    Mutowalność

    Niektóre obiekty można zmieniać po utworzeniu. Nazywamy je mutowalnymi. Pozostałe są niemutowalne: żeby otrzymać inną wartość, trzeba użyć innego obiektu.

    MutowalneNiemutowalne
    list, dict, setint, float, str, tuple, frozenset

    Gdy dwie nazwy wskazują tę samą liczbę lub tekst, nie można przez jedną z nich zmienić zawartości tego obiektu. Listę i słownik można natomiast zmieniać.

    To ważne przy wywołaniu funkcji. Jej parametr może wskazywać tę samą listę co zmienna poza funkcją. Zmiana listy wewnątrz funkcji będzie wtedy widoczna również poza nią.

    def add_promo(calendar, day):
    calendar.append(day)
    return calendar

week = ["pon", "wt"]
weekend = add_promo(week, "sob")
print(week)
    • ['pon', 'wt']Funkcja nie dostała kopii. calendar wewnątrz funkcji to ta sama lista co week na zewnątrz.
    • ['pon', 'wt', 'sob']Tak. append zmienił listę w miejscu, a week wciąż na nią wskazuje. Funkcja zmieniła dane wywołującego.
    • Błąd: week nie istnieje wewnątrz funkcjiFunkcja nie używa nazwy week. Dostaje obiekt pod nazwą calendar.

    Podobna sytuacja występuje przy domyślnych argumentach funkcji. Wartość domyślna powstaje raz, podczas definiowania funkcji. Kolejne wywołania korzystają z tego samego obiektu:

    def collect(sale, basket=[]):
    basket.append(sale)
    return basket

collect(3)
print(collect(5))
    • [5]Tak by było, gdyby pusta lista powstawała przy każdym wywołaniu.
    • [3, 5]Tak. Oba wywołania dopisują do tej samej listy, która żyje razem z funkcją. Poprawny zapis to basket=None i utworzenie listy w środku.
    • Błąd: lista nie może być wartością domyślnąMoże. Python na to pozwala i dlatego to pułapka, a nie błąd składni.

    Kopia płytka i głęboka

    Żeby utworzyć kopię, trzeba o to poprosić wprost. Zapisy list(x), x.copy() i x[:] tworzą kopię płytką. Powstaje nowa kolekcja, ale jej elementy wskazują te same obiekty co elementy oryginału.

    Dla listy liczb zwykle to wystarczy. Jeśli jednak w środku są inne listy, pozostaną one wspólne. Zobacz, co stanie się w poniższym słowniku:

    stock = {"jabłka": [5, 3], "gruszki": [2, 2]}
snapshot = stock.copy()

stock["jabłka"].append(9)
stock["śliwki"] = [1]
print(snapshot)
    • {'jabłka': [5, 3], 'gruszki': [2, 2]}Tak działałaby kopia głęboka, copy.deepcopy(stock).
    • {'jabłka': [5, 3, 9], 'gruszki': [2, 2]}Tak. Nowy klucz nie trafił do kopii, bo słownik jest osobny. Lista pod kluczem jabłka jest jednak ta sama w obu słownikach.
    • {'jabłka': [5, 3, 9], 'gruszki': [2, 2], 'śliwki': [1]}To zawartość stock. snapshot jest osobnym słownikiem i nowych kluczy nie dostaje.
    Reguła

    W zadaniach kursu funkcja powinna pozostawiać przekazane dane bez zmian i zwracać osobny wynik. Jeśli celowo zmienia dane, zaznacz to w jej nazwie i docstringu.

    Do tej zasady wrócimy w module 06: funkcja czyszcząca dane będzie zwracać nową tabelę. Tutor sprawdza ją również podczas przeglądu Twojego kodu.

    Cztery kolekcje

    Python ma cztery wbudowane kolekcje, których będziesz używać codziennie. Różnią się tym, czy pamiętają kolejność, czy pozwalają na powtórzenia i czy da się je zmienić.

    TypPrzykładKolejnośćZmiennyDo czego
    list[3, 5, 4]taktakciąg wartości: sprzedaż miesiąc po miesiącu
    tuple("T1", "1998-01")takniestały zestaw pól: nazwa i data startu serii
    dict{"T1": 12}tak (kolejność wstawiania)takwyszukiwanie po kluczu: statystyki po nazwie serii
    set{"T1", "T7"}nietakprzynależność i unikalność: które serie mają braki

    Różnice między kolekcjami dotyczą też wyszukiwania. Zapis x in lista może wymagać sprawdzenia kolejnych elementów listy. Zbiór i słownik mają mechanizm szybkiego wyszukiwania po wartości lub kluczu. Przy dużych danych dobór kolekcji może więc istotnie zmienić czas działania programu.

    Listy nie można użyć jako klucza słownika ani elementu zbioru. Krotka może pełnić tę rolę, jeśli również każdy z jej elementów nadaje się na klucz, na przykład jest liczbą lub napisem.

    stock = {("sklep", 1): 10}
stock[("sklep", 1)] += 5
unique = set([3, 1, 3, 2, 1])
print(stock, len(unique))
    • {('sklep', 1): 15} 3Tak. Ta sama krotka trafia w ten sam klucz, a zbiór zostawia trzy różne wartości.
    • {('sklep', 1): 10, ('sklep', 1): 5} 5Słownik ma jeden wpis na klucz, a zbiór nie trzyma powtórzeń.
    • Błąd: krotka nie może być kluczemMoże, bo jest niezmienna. Kluczem nie może być lista.

    Sortowanie po kluczu

    sorted(kolekcja) zwraca nową listę, ułożoną rosnąco. Kolekcja, którą dostał, zostaje bez zmian. Argument key mówi, po czym sortować: to funkcja, którą sorted wywołuje dla każdego elementu. Elementy układa według tego, co ta funkcja zwróci.

    words = ["chleb", "ser", "masło"]
print(sorted(words, key=len))                         # ['ser', 'chleb', 'masło']

prices = [("ser", 12.5), ("chleb", 4.0)]
print(sorted(prices, key=lambda pair: pair[1]))       # [('chleb', 4.0), ('ser', 12.5)]

    lambda pair: pair[1] to krótka funkcja bez nazwy: dostaje element pair i zwraca jego drugie pole. Działa tak samo jak def z jedną linią return pair[1]. Więcej o takich funkcjach w module 02.

    Krotki Python porównuje pole po polu: najpierw pierwsze, a drugie tylko wtedy, gdy pierwsze są równe. Dlatego (1, "b") < (1, "c") daje True. Jeśli key zwraca krotkę, drugie pole rozstrzyga remisy w pierwszym.

    Comprehensions

    Pętla, która buduje nową kolekcję z elementów starej, ma w Pythonie krótszy zapis. Czyta się go jak zdanie: "weź to dla każdego elementu, który spełnia warunek".

    known = []
for value in values:
    if value is not None:
        known.append(value)

known = [value for value in values if value is not None]      # to samo
by_name = {name: sum(v) for name, v in series.items()}        # słownik
codes = {name[0] for name in series}                          # zbiór

    Comprehension tworzy nową kolekcję. W pokazywanych przykładach odczytujemy dane z oryginału i zapisujemy wynik osobno.

    Krótszy kod nie zawsze jest jednak czytelniejszy. Jeśli trudno prześledzić warunki i przekształcenia, użyj zwykłej pętli. Łatwiej będzie ją wyjaśnić i sprawdzić.

    values = [0, 2, None, 0, 5]
print([v * 10 for v in values if v])
    • [0, 20, 0, 50]Warunek if v odrzuca wszystko, co jest fałszywe w kontekście logicznym, a 0 jest fałszywe tak samo jak None.
    • [20, 50]Tak. if v odrzuca None, ale też zera. Jeśli chodzi Ci tylko o braki, pisz if v is not None.
    • Błąd: nie można mnożyć NoneNone nie dochodzi do mnożenia, bo odpada w warunku.
    Pułapka

    Zero oznacza znany wynik sprzedaży. None oznacza, że wyniku nie znamy. Warunek if v odrzuci obie wartości, więc do pomijania braków użyj dokładnego sprawdzenia is not None.

    Iteracja i generatory

    Pętla for pobiera kolejne elementy obiektu. Może przechodzić po liście, kluczach słownika, liniach pliku lub zakresie liczb. Pobieranie kolejnych elementów nazywamy iteracją. Pętla kończy się, gdy obiekt nie udostępnia już następnego elementu.

    Funkcja zawierająca yield tworzy generator. Przy wywołaniu nie oblicza od razu wszystkich wyników. Po rozpoczęciu iteracji wykonuje kod do yield, udostępnia wartość i czeka na kolejne pobranie.

    Dzięki temu można odczytywać duży plik linia po linii, bez przechowywania całego tekstu w pamięci.

    def data_lines(lines):
    for line in lines:
        if not line.startswith("#"):
            yield line.strip()
    def numbers():
    print("start")
    yield 1
    print("po jedynce")
    yield 2

gen = numbers()
print("utworzony")
print(next(gen))
    • start, utworzony, 1Wywołanie numbers() nie uruchamia ciała funkcji. Tworzy tylko generator.
    • utworzony, start, 1Tak. Ciało rusza dopiero przy pierwszym next i zatrzymuje się na pierwszym yield. "po jedynce" jeszcze się nie wypisało.
    • utworzony, start, 1, po jedynce, 2next prosi o jeden element, nie o wszystkie.

    Generator można przejść tylko raz. Druga pętla po tym samym generatorze nie zobaczy żadnego elementu. Jeśli potrzebujesz danych dwa razy, zapisz je do listy: list(gen).

    Pliki i with

    Po odczycie plik trzeba zamknąć, również wtedy, gdy wystąpi błąd. Blok with robi to automatycznie. Nie musisz dopisywać osobnego zamknięcia dla każdej możliwej ścieżki wykonania.

    from pathlib import Path

path = Path("data/raw/car_parts/car_parts_dataset_with_missing_values.tsf")
with path.open(encoding="utf-8") as handle:
    for line in handle:          # plik jest iterowalny: linia po linii
        ...
# tutaj plik jest już zamknięty

    Dwa nawyki na cały kurs:

    • Ścieżki składasz z pathlib.Path operatorem /, nie sklejasz napisów. Path("data") / "raw" / "plik.tsf" działa tak samo w Linuksie i w Windows.
    • Zawsze podajesz encoding="utf-8". Domyślne kodowanie zależy od systemu, a polskie znaki i symbole walut rozjeżdżają się pierwsze.

    Plik jest przykładem obiektu obsługującego with, czyli context managera. Taki obiekt przygotowuje zasób przy wejściu do bloku i porządkuje go przy wyjściu. Podobnie można zarządzać połączeniem z bazą danych lub blokadą.

    Zapis do pliku JSON

    JSON to tekstowy format zapisu danych, obsługiwany przez wiele języków programowania. Funkcja json.dumps zamienia słownik zawierający napisy, liczby, None i listy na tekst JSON.

    Opcja indent=2 dodaje wcięcia o szerokości dwóch spacji, a sort_keys=True porządkuje klucze alfabetycznie. Ułatwia to czytanie pliku i porównywanie jego wersji.

    import json
from pathlib import Path

text = json.dumps({"ser": 2, "chleb": None}, indent=2, sort_keys=True)
target = Path("out") / "demo" / "stock.json"
target.parent.mkdir(parents=True, exist_ok=True)    # katalog out/demo, jeśli go nie ma
target.write_text(text, encoding="utf-8")

    target.parent to katalog, w którym ma leżeć plik. mkdir(parents=True, exist_ok=True) tworzy go razem z brakującymi katalogami wyżej i nie zgłasza błędu, gdy już istnieje. write_text otwiera plik, zapisuje tekst i zamyka plik, więc with nie jest tu potrzebne.

    Wyjątki

    Wyjątek informuje, że program nie może wykonać danej operacji. Ma typ i komunikat. Na przykład ValueError oznacza niepoprawną wartość, KeyError brak klucza, a FileNotFoundError brak pliku. Komunikat powinien wskazać, które dane lub plik spowodowały problem.

    def parse_value(text):
    if text == "?":
        return None
    try:
        return float(text)
    except ValueError as error:
        raise ValueError(f"Not a number: {text!r}") from error

    Trzy zasady:

    • Łap konkretny typ. except ValueError, nie gołe except. Gołe łapie wszystko, także literówkę w nazwie zmiennej i Ctrl+C.
    • Nie ukrywaj przyczyny. Samo except: pass pozwala kontynuować program bez wyjaśnienia błędu. Obsłuż wyjątek wtedy, gdy możesz podjąć konkretną decyzję. W przeciwnym razie pozwól mu przerwać działanie albo dodaj kontekst i zgłoś go ponownie.
    • Komunikat z wartością. "Not a number: 'abc'" od razu mówi, co poszło nie tak. "Invalid input" nie mówi nic.
    def safe_total(values):
    total = 0
    for v in values:
        try:
            total += float(v)
        except:
            pass
    return total

print(safe_total(["1", "2", "?", "3O"]))
    • 6.0"3O" to trzy i litera O, nie zero. float go nie odczyta.
    • 3.0Tak. "?" i "3O" po cichu wypadły. Funkcja zwraca liczbę, która wygląda wiarygodnie, a jest zła. Tak wygląda cichy błąd.
    • Błąd: ValueErrorByłby, gdyby nie except: pass. I to byłoby lepsze zakończenie.
    Reguła

    W except podawaj konkretny typ wyjątku. Unikaj samego except, które obejmuje także nieoczekiwane problemy, oraz except: pass, które ukrywa błąd bez wyjaśnienia.
