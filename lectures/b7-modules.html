    Moduł, podstawowe typy i jakość kodu

    Twoja funkcja i testy staną się małym projektem, który można uruchomić także poza notebookiem. Zapiszesz potrzebne narzędzia, opiszesz typy danych i wykonasz sprawdzenia w terminalu.

    • Przed lekcją: B6.1 i B6.2. Własne summary.py i test_summary.py, oba w practice.
    • Jak pracować: przewiduj wyniki, uruchamiaj kod i wyjaśniaj to, co widzisz

    Zaimportuj funkcję z własnego pliku

    Plik summary.py jest modułem, czyli plikiem Pythona, z którego możesz korzystać w innym kodzie. Po import summary wywołasz funkcję jako summary.mean_known(...).

    Możesz też napisać from summary import mean_known. Wtedy używasz samej nazwy mean_known(...). Oba zapisy korzystają z tej samej funkcji z pliku summary.py.

    Przy pierwszym imporcie Python wykonuje zawartość pliku od góry do dołu. Jeśli na końcu pliku umieścisz uruchomienie raportu, import też go uruchomi. Zostaw w module definicję funkcji, a doświadczenia wykonuj w notebooku lub testach.

    Moduł ma na górze print("loading"). Co zrobią dwa importy w jednym świeżym procesie?

    • Wypiszą loading dwa razyImport nie wykonuje ponownie już załadowanego modułu bez dodatkowej operacji.
    • Wypiszą loading razKolejny import korzysta z zapamiętanego modułu.

    Kernel zapamiętuje zaimportowany moduł. Dlatego po zmianie summary.py kolejne import może nadal korzystać ze starej wersji.

    Zrestartuj kernel i uruchom notebook od początku, żeby wczytać aktualny plik. Testy uruchamiane przez pytest z terminala zaczynają pracę w nowym procesie i odczytują kod z dysku.

    Zapisz narzędzia projektu

    Otwórz terminal w folderze practice, w którym są Twoja funkcja i testy. To wspólny podprojekt w kopii repozytorium kursu. Notebooki nadal są w labs. Jeśli istnieje już w nim pyproject.toml, pomiń pierwsze polecenie uv init.

    cd practice
uv init --bare --python 3.12 --no-workspace --vcs none
uv python pin 3.12
uv add --dev pytest ruff mypy

    Każdy z utworzonych plików ma inne zadanie:

    • pyproject.toml opisuje projekt i potrzebne narzędzia.
    • .python-version wybiera Python 3.12.
    • uv.lock zapisuje wybrane wersje bibliotek.
    • Folder .venv zawiera środowisko utworzone na Twoim komputerze.

    Teraz uruchamiaj narzędzia przez uv run. Ich nazwy i wersje są zapisane w projekcie, więc nie potrzebujesz już opcji --no-project ani --with.

    uv run python -m pytest -q test_summary.py
uv run ruff format summary.py test_summary.py
uv run ruff check summary.py test_summary.py

    ruff format porządkuje układ kodu. ruff check szuka między innymi nieznanych nazw i nieużytych importów. Żadne z tych poleceń nie sprawdza, czy średnia ma poprawną wartość. To zadanie Twoich testów.

    Opisz argument i wynik

    Adnotacje typów opisują, jakich danych oczekuje funkcja i jaki wynik zwraca. Typ parametru zapisujemy po dwukropku, a typ wyniku po strzałce ->.

    Sam Python nie zamienia wartości na podstawie tych opisów. Narzędzie mypy czyta natomiast kod i wskazuje miejsca, w których typy się nie zgadzają:

    def triple(number: float) -> float:
    return number * 3

print(triple(2.0))

    list[float | None] oznacza listę liczb lub braków. Znak | łączy tu dwa dopuszczalne typy. Dopisz taki typ argumentu do własnej mean_known, a jako typ wyniku podaj float. Funkcje testowe kończą się bez zwracania wartości, więc dopisz im -> None.

    uv run mypy --disallow-untyped-defs summary.py
uv run ruff format --check summary.py test_summary.py
uv run ruff check summary.py test_summary.py
uv run python -m pytest -q test_summary.py

    Jeśli mypy wskazuje możliwe None w obliczeniu, sprawdź, gdzie odrzucasz brakujące wartości. Narzędzie musi widzieć ten warunek przed użyciem liczby. Popraw przyczynę komunikatu zamiast go wyciszać. Na tym etapie wystarczą poznane podstawowe typy.

    Czy adnotacja -> float automatycznie zamienia wynik na float?

    • TakPython sam nie wykonuje konwersji na podstawie tej adnotacji.
    • NieTyp opisuje umowę. Konwersję musi wykonać kod, jeśli jest potrzebna.
