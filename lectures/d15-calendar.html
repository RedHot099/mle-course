    Co wiadomo z wyprzedzeniem

    Dzień tygodnia przyszłej daty jest znany. Rzeczywista sprzedaż nie jest. Kalendarz może więc wzbogacić model bez użycia przyszłych pomiarów.

    Identyfikator produktu zapisany cyframi nadal jest kategorią. Model liniowy nie powinien zakładać, że produkt 20 ma dwukrotnie większy wkład niż produkt 10. One-hot encoding tworzy osobną kolumnę wskaźnikową dla kategorii.

    import pandas as pd
x = pd.DataFrame({"day": pd.to_datetime(["2024-01-01","2024-01-02"]), "item":["bread","fruit"]})
print(x["day"].dt.dayofweek.tolist())
print(pd.get_dummies(x["item"], dtype=int))

    Kategorie treningu i nowe wartości

    Liczba kolumn i ich znaczenie muszą być takie same przy uczeniu i prognozie. W projekcie użyj OneHotEncoder(handle_unknown="ignore") dopasowanego wyłącznie na treningu i połączonego przez ColumnTransformer z cechami liczbowymi. Nie dopasowuj osobnego kodera do walidacji.

    Na początek użyj poznanych wskaźników kategorii. Ustal ich znaczenie na treningu i zachowaj je przy prognozowaniu.

    import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import OneHotEncoder
X = pd.DataFrame({"item":["a","b","a"], "lag1":[2.,3.,4.]})
prepare = ColumnTransformer([
    ("item", OneHotEncoder(handle_unknown="ignore", sparse_output=False), ["item"])
], remainder="passthrough")
print(prepare.fit_transform(X).shape)
print(prepare.transform(pd.DataFrame({"item":["c"],"lag1":[5.]})))

    Pierwszy element krotki nazywa etap, drugi wskazuje przekształcenie, trzeci kolumny. remainder="passthrough" zachowuje pozostałe kolumny, a sparse_output=False wybiera zwykłą tablicę. Nieznana kategoria c otrzyma zera w poznanych kolumnach kategorii. Obiekt prepare możesz umieścić przed Ridge w make_pipeline, zamiast osobno dopasowywać go do walidacji.
