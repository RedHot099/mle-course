    A3 · Ścieżka A i B

    Przenieś pracę do notebooka

    Zapiszesz notebook lokalnie, uruchomisz go od początku i rozpoznasz trzy różne miejsca wpisywania poleceń.

    • Przed lekcją: Podstawy Python z A2 albo zaliczona diagnoza.
    • Tryb: najpierw przewidź, potem wykonaj i wyjaśnij

    Terminal, edytor i kernel

    MiejsceCo tam wpisujeszPrzykład
    Terminal systemuPolecenia uruchamiające programyuv --version
    Komórka notebookaKod Pythonprint(2 + 3)
    Edytor pliku .pyKod, który zapisujesz przed uruchomieniemprint("ready")

    Kernel to proces Python wykonujący komórki notebooka. Pamięta nazwy między uruchomieniami komórek. Zapisany plik notebooka nie jest tym samym co pamięć kernela.

    Dwa środowiska

    Runner na stronach A i B wykonuje każde Uruchom i Sprawdź w nowej przestrzeni nazw. Kod jednego pola nie przekazuje zmiennych do następnego. W lokalnym notebooku komórki współdzielą kernel. Dlatego uruchamianie notebooka od początku jest ważną kontrolą.

    Przygotuj terminal

    Na Linuxie otwórz terminal. Na Windowsie używamy Linuxa w WSL2. Jeśli masz działające Ubuntu w WSL, otwórz jego terminal. Jeśli jeszcze go nie masz, wykonaj tylko część Windows istniejącej instrukcji, pomijając na razie opcjonalny sterownik NVIDIA. Potem wróć tutaj. Nie musisz teraz przechodzić całej lekcji 00.

    Instalacja na komputerze współdzielonym może wymagać pomocy jego właściciela. Wtedy kontynuuj A i B w przeglądarce, a kroki lokalne wykonaj później. Nie jest to niezaliczenie zadania programistycznego.

    W terminalu Linux sprawdź uv:

    uv --version

    Jeśli widzisz numer wersji, pomiń instalację. Jeśli polecenie nie istnieje, zainstaluj uv instrukcją użytkownika z oficjalnej dokumentacji. Na Linuxie i w terminalu WSL jest to:

    curl --retry 5 --retry-all-errors -LsSf https://astral.sh/uv/install.sh | sh

    Zamknij i otwórz terminal. Ponownie sprawdź uv --version. Nie wpisuj powyższych poleceń do komórki Python.

    Utwórz osobne miejsce do nauki

    Pracujemy w Twoim katalogu domowym, w osobnym folderze. mkdir -p tworzy folder, cd przechodzi do niego, a pwd pokazuje bieżącą ścieżkę.

    mkdir -p ~/mle-practice
cd ~/mle-practice
pwd
uv run --no-project --python 3.12 python -c "print(2 + 3)"

    Ostatni wynik powinien wynosić 5. Opcja --no-project pozwala wykonać program bez instalowania całego projektu ML. --python 3.12 wybiera wersję Pythona. Uv pobierze ją, jeśli jej brakuje. Nie potrzebujesz jeszcze git, danych FreshRetailNet ani bibliotek ML.

    Uruchom i zapisz notebook

    Z tego samego terminala uruchom:

    uv run --no-project --python 3.12 --with jupyterlab --with ipykernel jupyter lab

    Uv przygotowuje oddzielne środowisko z JupyterLab. Terminal wypisze adres lokalnej strony. Otwórz go na swoim komputerze. Zostaw terminal uruchomiony. Jeśli korzystasz z WSL, adres otwierasz w przeglądarce Windows.

    1. W JupyterLab wybierz nowy notebook z kernelem Python 3.
    2. Nazwij plik first_steps.ipynb.
    3. W pierwszej komórce wpisz stock = 6 i uruchom ją przez Shift+Enter.
    4. W drugiej wpisz print(stock + 2). Oczekiwany wynik to 8.
    5. Zapisz notebook przez Ctrl+S.
    6. W menu Kernel wybierz Restart Kernel and Run All Cells. Nazwa może nieznacznie różnić się między wersjami. Ponownie powinieneś zobaczyć 8.

    Teraz otwórz drugi nowy notebook, bez definiowania stock, i wykonaj print(stock). Zobaczysz NameError. To celowe doświadczenie: wynik zależy od wcześniejszych poleceń w danym kernelu.

    Zakończenie pracy

    Po wykonaniu zamknij niepotrzebny kernel przez menu Kernel → Shut Down Kernel. Serwer Jupyter zatrzymasz przez Ctrl+C w jego terminalu i potwierdzenie. Nie wyłączasz w ten sposób komputera.

    Sprawdź środowisko, nie rozwiązanie

    Gotowość oznacza, że potrafisz zapisać notebook, zamknąć go, otworzyć i wykonać od początku. Zapisz w komórce tekstowej: gdzie leży plik, co wykonuje kernel i po czym rozpoznajesz wynik.

    Gdzie wpiszesz uv --version?

    • W terminaluTo polecenie uruchamiające program uv.
    • W komórce PythonZwykła komórka oczekuje składni Python, a nie polecenia terminala.

    Jeśli notebook nie startuje, zachowaj nazwę polecenia i treść błędu bez tokenu z adresu Jupyter. Wróć do runnera. Jeśli startuje, ale Twój kod daje zły wynik, dalsza praca dotyczy rozwiązania, nie instalacji.
