    Pierwsze własne testy

    Napiszesz test na małych danych, sprawdzisz wyjątek i zobaczysz, czy test zauważa błąd.

    • Przed lekcją: Własna funkcja mean_known z B6.1. Do pytest lokalnie potrzebne A3; pierwsze doświadczenie działa w przeglądarce.
    • Tryb: najpierw przewidź, potem wykonaj i wyjaśnij

    Oczekiwany wynik policz sam

    assert sprawdza zdanie. Jeśli jest prawdziwe, program idzie dalej. Jeśli fałszywe, zgłasza AssertionError. Wiadomość po przecinku pomaga nazwać niespełnione wymaganie.

    result = 2 + 3
assert result == 5, "Suma 2 i 3 powinna wynosić 5"
print("check passed")

    Wynikiem jest check passed. Test nie ma powtarzać obliczenia funkcji po drugiej stronie porównania. Oczekiwana wartość ma wynikać z ręcznego rachunku i umowy.

    Które sprawdzenie ma niezależne oczekiwanie?

    • assert length_cm(2) == 200Wiemy z przelicznika, że dwa metry to 200 cm.
    • assert length_cm(2) == length_cm(2)Obie strony korzystają z tego samego kodu, więc wspólny błąd pozostanie niezauważony.

    Zapisz funkcję i pierwszy test

    W JupyterLab z A3 wybierz nowy plik tekstowy. Zapisz go jako summary.py w katalogu mle-practice. Przenieś do niego własną funkcję mean_known, bez wywołań print z końca ćwiczenia. Plik .py jest modułem. Inny plik może importować jego definicje.

    Obok zapisz test_summary.py. Pierwszy test jest dostarczony jako wzór. Nie podaje sposobu obliczenia średniej.

    from summary import mean_known

def test_mean_includes_zero():
    assert mean_known([0, None, 6]) == 3.0

    Import from summary import mean_known bierze funkcję z pliku summary.py. Oba pliki leżą w tym samym katalogu. Pytest rozpoznaje pliki i funkcje zaczynające się od test_. Uruchom w terminalu tego katalogu:

    cd ~/mle-practice
uv run --no-project --python 3.12 --with pytest pytest -q

    Jeśli Twoja funkcja spełnia ten przypadek, zobaczysz 1 passed. Jeśli nie, pytest pokaże oczekiwany i otrzymany wynik. Brak modułu summary zwykle oznacza inny katalog albo niepoprawną nazwę pliku, nie brak biblioteki z internetu.

    Liczby przybliżone i oczekiwane błędy

    Liczby float przechowują przybliżenia. Zamiast wymagać dokładnej równości wyniku niekończącego się ułamka, użyj pytest.approx. Do sprawdzenia oczekiwanego wyjątku służy pytest.raises. To gotowe narzędzia, nie klasy do napisania.

    import pytest

def half(value):
    if value < 0:
        raise ValueError("value must be non-negative")
    return value / 2

def test_half():
    assert half(1) == pytest.approx(0.5)

def test_half_rejects_negative():
    with pytest.raises(ValueError, match="non-negative"):
        half(-1)

    Ten przykład używa innej funkcji niż zadanie. match sprawdza fragment komunikatu. Jeśli wyjątek nie wystąpi, test ma się nie udać. Przepisanie przykładu do testów mean_known wymaga wybrania jej własnych przypadków i oczekiwań.

    Dopisz testy własnej funkcji

    Do test_summary.py dopisz co najmniej cztery własne testy. Wybierz: pustą listę, same braki, wynik ułamkowy oraz zachowanie wejścia. Dla każdego najpierw zapisz oczekiwanie słowami. Nie kopiuj całej pętli z implementacji do testu.

    1. Uruchom testy na swojej funkcji.
    2. W kopii pliku wprowadź jeden kontrolowany błąd, na przykład pomijanie zer.
    3. Sprawdź, czy testy przestają przechodzić i czy komunikat dotyczy tego błędu.
    4. Przywróć poprawną wersję i uruchom komplet ponownie.

    Robisz to na swoim małym module, nie na kodzie reszty kursu. Nie musisz jeszcze znać narzędzi mutation testing.

    Rubryka samooceny bez tutora

    Testy przechodzą na Twojej poprawnej wersji, a co najmniej jeden pada po kontrolowanym zepsuciu. Każdy sprawdza konkretne wymaganie. Oczekiwany błąd nie jest zamieniany na puste except. Wejście do testu jest małe i widoczne w jego treści. Liczba zaliczonych testów sama nie dowodzi jakości.

    Powrót bez zaglądania

    Czy zielony test dowodzi, że funkcja działa na wszystkich danych?

    Sprawdź własne wyjaśnienie

    Nie. Dowodzi tylko zgodności z wybranymi przypadkami. Potrzebne są przypadki odróżniające poprawne zachowanie od typowego błędu. Nowy przykład po przerwie sprawdza także Twoje rozumienie.
