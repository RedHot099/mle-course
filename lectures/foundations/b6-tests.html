    Pierwsze własne testy

    Skąd wiedzieć, czy funkcja działa poprawnie po kolejnej zmianie? Zapiszesz oczekiwane wyniki jako testy. Potem celowo wprowadzisz błąd do własnego kodu i sprawdzisz, czy testy go wykryją.

    • Przed lekcją: Przygotuj własną funkcję mean_known z B6.1. Pierwszy przykład działa w przeglądarce. Do uruchomienia pytest na komputerze potrzebujesz środowiska z A3.
    • Jak pracować: przewiduj wyniki, uruchamiaj kod i wyjaśniaj to, co widzisz

    Oczekiwany wynik policz sam

    Polecenie assert sprawdza warunek. Gdy warunek jest prawdziwy, program wykonuje kolejne polecenie. Gdy jest fałszywy, zgłasza AssertionError. Tekst po przecinku opisuje, czego oczekiwaliśmy:

    result = 2 + 3
assert result == 5, "Suma 2 i 3 powinna wynosić 5"
print("check passed")

    Program wypisze check passed. Wartość oczekiwaną w teście ustal na podstawie opisu funkcji i własnego rachunku.

    Nie obliczaj jej tą samą funkcją, którą właśnie sprawdzasz. Jeśli funkcja ma błąd, dostaniesz ten sam błędny wynik po obu stronach porównania, a test mimo to przejdzie.

    Który test porównuje wynik funkcji z wartością ustaloną niezależnie?

    • assert length_cm(2) == 200Wiemy z przelicznika, że dwa metry to 200 cm.
    • assert length_cm(2) == length_cm(2)Obie strony korzystają z tego samego kodu, więc wspólny błąd pozostanie niezauważony.

    Zapisz funkcję i pierwszy test

    W JupyterLab utwórz plik tekstowy summary.py w folderze mle-practice. Wklej do niego własną funkcję mean_known z B6.1. Pomiń wywołanie print spod definicji. Plik z rozszerzeniem .py jest modułem, z którego możesz importować funkcje.

    W tym samym folderze utwórz test_summary.py. Zapisz w nim poniższy pierwszy test. Sprawdza wynik funkcji na małym wejściu, nie opisuje sposobu obliczenia średniej.

    from summary import mean_known

def test_mean_includes_zero():
    assert mean_known([0, None, 6]) == 3.0

    Instrukcja from summary import mean_known udostępnia funkcję z pliku summary.py. Narzędzie pytest znajduje pliki i funkcje, których nazwy zaczynają się od test_, i wykonuje ich sprawdzenia. Uruchom je w terminalu z folderu zawierającego oba pliki:

    cd ~/mle-practice
uv run --no-project --python 3.12 --with pytest pytest -q

    Gdy funkcja zwraca oczekiwany wynik, zobaczysz 1 passed. W przeciwnym razie pytest pokaże różnicę. Jeśli nie może zaimportować summary, sprawdź nazwę pliku i bieżący folder przed instalowaniem dodatkowych bibliotek.

    Liczby przybliżone i oczekiwane błędy

    Liczby typu float mają ograniczoną precyzję. Dlatego wynik poprawnego obliczenia może nieznacznie różnić się od liczby zapisanej w teście. Do takiego porównania użyj pytest.approx, które dopuszcza niewielką różnicę.

    Test może też sprawdzać, czy funkcja zgłasza oczekiwany wyjątek. Służy do tego pytest.raises:

    import pytest

def half(value):
    if value < 0:
        raise ValueError("value must be non-negative")
    return value / 2

def test_half():
    assert half(1) == pytest.approx(0.5)

def test_half_rejects_negative():
    with pytest.raises(ValueError, match="non-negative"):
        half(-1)

    W tym przykładzie match sprawdza fragment komunikatu wyjątku. Jeśli wyjątek nie wystąpi, test zakończy się niepowodzeniem. W testach własnej funkcji dobierz wejścia i komunikaty do jej umowy.

    Dopisz testy własnej funkcji

    W pliku test_summary.py dopisz cztery testy swojej funkcji. Sprawdź pustą listę, listę samych braków, wynik z częścią ułamkową oraz to, czy funkcja nie zmienia przekazanej listy.

    Przed napisaniem każdego testu ustal, czego oczekujesz. Policz wynik ręcznie albo wskaż, jaki błąd powinien wystąpić. W teście sprawdzasz rezultat działania funkcji, więc nie przepisuj do niego sposobu obliczania średniej.

    1. Uruchom testy na swojej funkcji.
    2. W kopii pliku wprowadź jeden kontrolowany błąd, na przykład pomijanie zer.
    3. Sprawdź, czy testy przestają przechodzić i czy komunikat dotyczy tego błędu.
    4. Przywróć poprawną wersję i uruchom komplet ponownie.

    Wszystkie próby wykonuj na swoim małym module. Nie potrzebujesz dodatkowych narzędzi: wprowadzisz jedną zmianę w kodzie i zobaczysz, jak zareagują testy.

    Sprawdź swoje testy

    Przed celową zmianą wszystkie testy powinny przechodzić. Po wprowadzeniu błędu przynajmniej jeden powinien się nie udać, a po naprawie znów przejść.

    Przeczytaj każdy test osobno. Czy widzisz w nim małe dane i konkretny oczekiwany wynik? Jeśli sprawdzasz wyjątek, upewnij się też, że test nie przechodzi wtedy, gdy funkcja tego wyjątku nie zgłasza.

    Sprawdź, co pamiętasz

    Czy zielony test dowodzi, że funkcja działa na wszystkich danych?

    Sprawdź własne wyjaśnienie

    Przejście testu potwierdza wynik dla danych, które ten test sprawdził. Dobieraj przypadki, na których typowe błędy dają inną odpowiedź niż poprawna funkcja. Po przerwie sprawdź też nowe wejście i wyjaśnij jego wynik bez zaglądania do kodu.
