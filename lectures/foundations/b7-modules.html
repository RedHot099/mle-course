    B7.1 · Ścieżka A i B

    Moduł, podstawowe typy i jakość kodu

    Zbierz własną funkcję i testy w mały projekt. Zapisz potrzebne narzędzia, dodaj podstawowe typy i uruchom sprawdzenia z terminala.

    • Przed lekcją: B6.1 i B6.2. Własne summary.py i test_summary.py, oba w mle-practice.
    • Tryb: najpierw przewidź, potem wykonaj i wyjaśnij

    Zaimportuj funkcję z własnego pliku

    Plik summary.py jest modułem. Po import summary możesz wywołać funkcję przez summary.mean_known(...). Zapis from summary import mean_known pozwala wywołać ją bez nazwy modułu. Obie formy korzystają z funkcji zapisanej w tym samym pliku.

    Przy pierwszym imporcie Python wykonuje zawartość pliku od góry do dołu. Jeśli na końcu pliku umieścisz uruchomienie raportu, import też go uruchomi. Zostaw w module definicję funkcji, a doświadczenia wykonuj w notebooku lub testach.

    Moduł ma na górze print("loading"). Co zrobią dwa importy w jednym świeżym procesie?

    • Wypiszą loading dwa razyImport nie wykonuje ponownie już załadowanego modułu bez dodatkowej operacji.
    • Wypiszą loading razKolejny import korzysta z zapamiętanego modułu.

    Kernel pamięta zaimportowany moduł. Po zmianie summary.py uruchom notebook ponownie od początku po restarcie kernela. Sam kolejny import może nadal korzystać z poprzedniej wersji. Pytest uruchomiony z terminala wykonuje kod w nowym procesie.

    Zapisz narzędzia projektu

    Otwórz terminal w folderze mle-practice, w którym są Twoja funkcja i testy. To osobny projekt, nie folder mle-course. Jeśli istnieje już w nim pyproject.toml, pomiń pierwsze polecenie uv init.

    cd ~/mle-practice
uv init --bare --python 3.12
uv python pin 3.12
uv add --dev pytest ruff mypy

    W projekcie powstają pliki o różnych zadaniach:

    • pyproject.toml opisuje projekt i potrzebne narzędzia.
    • .python-version wybiera Python 3.12.
    • uv.lock zapisuje wybrane wersje bibliotek.
    • Folder .venv zawiera środowisko utworzone na Twoim komputerze.

    Teraz uruchamiaj narzędzia przez uv run. Ich nazwy i wersje są zapisane w projekcie, więc nie potrzebujesz już opcji --no-project ani --with.

    uv run pytest -q
uv run ruff format summary.py test_summary.py
uv run ruff check summary.py test_summary.py

    ruff format porządkuje układ kodu. ruff check szuka między innymi nieznanych nazw i nieużytych importów. Żadne z tych poleceń nie sprawdza, czy średnia ma poprawną wartość. To zadanie Twoich testów.

    Opisz argument i wynik

    Adnotacja typu opisuje oczekiwane dane i wynik. Typ argumentu piszesz po dwukropku, a typ wyniku po strzałce ->. Python nie zmienia wartości na podstawie adnotacji. Osobne narzędzie, mypy, sprawdza zgodność typów w kodzie:

    def triple(number: float) -> float:
    return number * 3

print(triple(2.0))

    list[float | None] oznacza listę liczb lub braków. Znak | łączy tu dwa dopuszczalne typy. Dopisz taki typ argumentu do własnej mean_known, a jako typ wyniku podaj float. Funkcje testowe kończą się bez zwracania wartości, więc dopisz im -> None.

    uv run mypy --disallow-untyped-defs summary.py
uv run ruff format --check summary.py test_summary.py
uv run ruff check summary.py test_summary.py
uv run pytest -q

    Jeśli mypy wskazuje możliwe None w obliczeniu, sprawdź, gdzie odrzucasz brakujące wartości. Narzędzie musi widzieć ten warunek przed użyciem liczby. Popraw przyczynę komunikatu zamiast go wyciszać. Na tym etapie wystarczą poznane podstawowe typy.

    Czy adnotacja -> float automatycznie zamienia wynik na float?

    • TakPython sam nie wykonuje konwersji na podstawie tej adnotacji.
    • NieTyp opisuje umowę. Konwersję musi wykonać kod, jeśli jest potrzebna.

    Uruchom od czystego startu

    Uruchom z terminala cztery sprawdzenia pokazane wyżej. Zapisz, które bada wyniki, które typy, a które format i wzorce w kodzie. Dodaj do README.md instrukcję uruchomienia testów, aby inna osoba mogła je powtórzyć.

    Sprawdź własną odpowiedź

    Osoba czytająca projekt powinna znaleźć funkcję, jej docstring i polecenie uruchomienia testów. Format, lint, mypy oraz pytest mają przechodzić dla Twojego małego projektu. Nie wymagamy ukończenia późniejszych zadań z repozytorium kursu.

    Powrót bez zaglądania

    Dlaczego po zmianie pliku notebook może nadal używać starej funkcji?

    Sprawdź własne wyjaśnienie

    Import korzysta z modułu zapamiętanego w kernelu. Restart i wykonanie komórek od początku pozwalają wczytać bieżący plik. Ponowna instalacja Pythona nie jest do tego potrzebna.
