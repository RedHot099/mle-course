    B7.1 · Ścieżka A i B

    Moduł, podstawowe typy i jakość kodu

    Uruchomisz swój moduł i testy w małym projekcie z powtarzalnymi zależnościami.

    • Przed lekcją: B6.1 i B6.2. Własne summary.py i test_summary.py, oba w mle-practice.
    • Tryb: najpierw przewidź, potem wykonaj i wyjaśnij

    Import nie jest kopiowaniem pliku

    Plik .py to moduł. import summary daje nazwę modułu, a potem summary.mean_known(...) wybiera jego funkcję. from summary import mean_known daje bezpośrednią nazwę funkcji. Oba zapisy działają na tym samym kodzie.

    Przy pierwszym imporcie Python wykonuje plik od góry. Dlatego nie trzymaj na jego końcu automatycznego wczytania danych ani uruchomienia raportu. Definicje zostają, doświadczenia wykonuje notebook lub osobny skrypt.

    Moduł ma na górze print("loading"). Co zrobią dwa importy w jednym świeżym procesie?

    • Wypiszą loading dwa razyImport nie wykonuje ponownie już załadowanego modułu bez dodatkowej operacji.
    • Wypiszą loading razKolejny import korzysta z zapamiętanego modułu.

    Gdy zmienisz summary.py w notebooku, sam ponowny import może nie pokazać nowej wersji. Na tym etapie zrestartuj kernel i wykonaj komórki od początku. Każde uruchomienie pytest z terminala zaczyna nowy proces.

    Zapisz narzędzia projektu

    Poniższe polecenia dotyczą osobnego katalogu mle-practice, nie korzenia repozytorium mle-course. Jeśli jest w nim już pyproject.toml, pomiń uv init.

    cd ~/mle-practice
uv init --bare --python 3.12
uv python pin 3.12
uv add --dev pytest ruff mypy

    pyproject.toml opisuje projekt i potrzebne narzędzia. .python-version wybiera Python 3.12 przy kolejnych uruchomieniach. uv.lock zapisuje rozwiązane wersje zależności. .venv zawiera lokalne środowisko projektu. Od tej chwili polecenia uruchamiasz przez uv run, bez --no-project i --with.

    uv run pytest -q
uv run ruff format summary.py test_summary.py
uv run ruff check summary.py test_summary.py

    Ruff format układa zapis kodu. Ruff check szuka między innymi nieznanych nazw i nieużytych importów. Zielony ruff nie potwierdza poprawnego wyniku średniej, dlatego testy nadal są potrzebne.

    Opisz argument i wynik

    Adnotacja typu to informacja dla czytelnika i narzędzi. Sama nie zmienia wykonywania kodu. Zapis po dwukropku dotyczy argumentu, a po strzałce wyniku.

    def triple(number: float) -> float:
    return number * 3

print(triple(2.0))

    list[float | None] opisuje listę liczb lub braków. Znak | oznacza tutaj alternatywę typów. Do własnej funkcji mean_known dopisz te typy argumentu oraz float wyniku. Do funkcji testowych, które nic nie zwracają, dopisz -> None.

    uv run mypy --disallow-untyped-defs summary.py
uv run ruff format --check summary.py test_summary.py
uv run ruff check summary.py test_summary.py
uv run pytest -q

    Nie musisz teraz typować dekoratorów ani znać Sequence, Protocol czy ABC. Jeśli mypy widzi możliwe None, wskaż zmienną, dla której wcześniej sprawdziłeś brak. Nie dopisuj ignore tylko po to, by zniknął komunikat.

    Czy adnotacja -> float automatycznie zamienia wynik na float?

    • TakPython sam nie wykonuje konwersji na podstawie tej adnotacji.
    • NieTyp opisuje umowę. Konwersję musi wykonać kod, jeśli jest potrzebna.

    Uruchom od czystego startu

    Zamknij kernel, a w terminalu tego projektu uruchom cztery sprawdzenia powyżej. Zapisz, które narzędzie sprawdza wynik, które typy, a które format i wzorce. Umieść w README.md krótką instrukcję uruchomienia testów.

    Rubryka samooceny

    Obcy czytelnik widzi nazwę pliku z funkcją, umowę w docstringu i polecenie testów. Format, lint, mypy oraz pytest przechodzą dla Twoich dwóch plików. Do B nie muszą przechodzić testy z nieukończonych modułów całego kursu.

    Powrót bez zaglądania

    Dlaczego po zmianie pliku notebook może nadal używać starej funkcji?

    Sprawdź własne wyjaśnienie

    Kernel może pamiętać załadowany moduł. Restart i wykonanie od początku odtwarza bieżący kod. Nie oznacza to, że trzeba ponownie instalować bibliotekę.
